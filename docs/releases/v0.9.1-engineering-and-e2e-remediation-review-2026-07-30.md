## 3. Engineering closure

### 3.1 Quote Line is now an aggregate-safe Command boundary

`quote.add_line`, `quote.update_line`, `quote.remove_line`, and
`quote.restore_line` are declared in both supported Quote manifests and the
architecture inventory. The generic record HTTP routes delegate Quote Line
mutations to those Commands rather than committing generic CRUD and
recalculating afterward.

Each Command performs one atomic effect containing:

- the child line mutation;
- the authoritative derived `line_total`;
- Quote subtotal, discount, tax, total, and aggregate version;
- the Command event, audit record, and execution record.

Only draft Quotes are editable. Missing lines, zero quantity, invalid moves,
and stale expected versions fail before committing. Soft deletion removes a
line from totals, restoration reintroduces it, and hard deletion also removes
its extension values. Revision, conversion, Invoice, customer-access, and
document paths consistently ignore deleted lines.

### 3.2 Workflow health and timer behavior fail closed

Demo Workflow seed errors are collected and propagated. `loadPackDemoData()`
records `demo_data_status = error` with the reason instead of overwriting the
failure with `loaded`; an already-errored instance is not treated as an
idempotent success.

Due timers are actionable only while their Work Item is `ready` or `active`.
The Cron boundary now has explicit GET/POST authorization tests, while
workflow concurrency tests cover the terminal-state defense.

## 4. E2E design closure

### 4.1 G1 API evidence

The business walkthrough emits a machine-readable, schema-versioned result
containing the exact Git SHA, working-tree state, environment, durations,
Scenario results, fresh record IDs, artifacts, failures, and final decision.
It has exactly five canonical API Scenarios and never substitutes seeded
records when a current-run aggregate or projection is absent. Planning and
form assertions are bound to records created by the same run.

Preflight and unexpected crashes still produce a complete artifact: missing
Scenarios become `BLOCKED`, the decision cannot be PASS, and the process exits
non-zero. `scripts/validate-e2e-result.mjs` independently validates provenance,
status vocabulary, evidence, Scenario count, freshness, and PASS invariants.

### 4.2 G2 browser evidence

The Playwright suite refuses to run as binding evidence unless all of these
conditions hold:

1. the API artifact is valid and PASS;
2. its exact SHA matches the current checkout;
3. both the artifact and current working tree are clean;
4. every canonical fresh record ID is present.

It then exercises owner, sales, dispatcher, technician, and supervisor
surfaces using the same fresh records on desktop Chrome and a Pixel 7 profile.
Assertions cover meaningful page content, semantic record projection,
interactivity, Next.js error overlays, console/page errors, and horizontal
overflow. Screenshots, traces, failure video, JSON, list, and HTML reports are
retained.

An API PASS remains G1 evidence only. It cannot replace the browser/device,
provider exception, or customer evidence required by later gates.
