## Stance

G3 asks whether a person with a job to do can **find the next step and trust
the surface**. This catalog treats the Agent browser sample as an **experience
audit**, not a functional re-test of G2.

Role lenses used:

- **Owner / office** — Quote → WO → Invoice → ask customer to pay
- **Sales Manager** — recognize and approve the right Quote
- **Technician** — pick today’s visit and finish the form on `/m`
- **Customer** — understand job status and pay without Runory jargon

Severity follows [manual E2E](../testing/manual-e2e/README.md) §4. Items marked
**UX-P1** are experience majors (wrong actor, mischarge risk, unrecognizable
work) even when the governed path can still complete.

## A. Detail pages (Quote / Work Order / Invoice)

| ID | Sev | Problem | Why it hurts | Where |

| UX-A1 | UX-P1 | Page H1 is the **object type** (“Work Order”, “Quotes”), not quote number / job title | Operator loses orientation; must hunt Basic Info for identity | `ObjectDetailPage` uses `record.name ?? title` where `title` is the type label |

| UX-A6 | P2 | On Work Order, default payment amount can be **0** with no WO total helper | Operator invents cents without commercial context | payment prefill logic |
| UX-A7 | P2 | Business actions use **internal vocabulary** (“governed commands”, “Triage”, “Mark as sent”) | Fine for power users; cold for new Owner | Business actions strip |

## Recommended fix order (experience, not G2 automation)

1. **Trust & money (UX-P1):** ~~A2 minor→major currency UI~~; ~~A3 request payment = copyable customer link~~; ~~D1 provider-first portal brand~~; ~~D2 hide persona on `/access`~~.
2. **Recognize the work (UX-P1):** ~~A1 record identity in H1~~; ~~B1 / C1 / C2 subject titles + human assignee/site on cards~~.
3. **Lifecycle clarity (P2):** ~~A4 hide payment until eligible (or existing requests)~~; ~~D3 omit “Not yet scheduled” when completed~~; ~~D4 schedule truth from visits~~; ~~B2 Claim vs Approve~~; ~~B4 Return for changes~~; ~~A8 office Record customer acceptance~~; ~~A6 commercial amount prefill~~; ~~D6 checkout locale~~; ~~A7 Next actions language~~; ~~A9 payment card demotion~~.
4. **Field continuity (P2):** ~~C7 form → visit~~; ~~C6 light CTA demotion~~; ~~C4 no raw visit IDs~~; ~~C5 field-path i18n (touched)~~; ~~B3 step display names~~; ~~B5 decision modal~~; remaining E4 holes elsewhere.
5. **Progress visibility (P2):** ~~A10 commands in header toolbar~~; ~~A11 header status badge~~; ~~A12 declared lifecycle spine~~; ~~A13 stage bar dated from governed events~~; ~~A14 sticky header~~; ~~B6 named actors in the event trail~~.

**Batch 1 shipped (no design debate):** UX-A1, UX-A2, UX-A3, UX-A4, UX-C1 (hide raw ids), UX-D2, UX-D3.

**Batch 1.1 (architecture polish):** payment/refund copy moved to `MessageKey` (en+zh);
shared `apps/cloud/src/lib/money.ts` keeps API/domain in minor units while UI uses
major units + `Intl` formatting; detail H1 uses `recordDisplayName`.

**Batch 2 decisions (locked + implemented):**

| --- | --- |

| UX-D4 / D3 | Prefer Visit schedule window; upcoming without window → **Scheduling in progress**; completed/cancelled without window → omit schedule row; show site when available |
| UX-C2 / B1 | Server-side enrichment (`company_name`, `site_name`, `quote_number`, amount); cards: primary `Company · Site` / `Quote # · Company`, secondary job title |
| UX-B2 | Claim is **optional** for permission-group queues (“Claim to own”); Approve primary without requiring Claim; hide Claim for named-user assignees |
| UX-B4 | Approval decline labeled **Return for changes** (not Reject) |
| UX-A8 | Office `quote.accept` → **Record customer acceptance** (secondary); portal keeps Accept quote |
| UX-C7 | Form success returns to **Visit detail** when subject is `service_visit` |
| UX-C6 | Light pass: one primary visit CTA by status; Cancel demoted |

**Batch 5 decisions (locked + implemented):**

| ID | Decision |
| --- | --- |
| UX-A10 | Record commands move from a content-area card into the **header toolbar** (advance commands visible, destructive behind `…`), matching Salesforce/Dynamics/ServiceNow convention instead of a guidance card; Batch 4's "Next actions" card retired |
| UX-A11 | Detail header carries a **status badge** using the lifecycle vocabulary, so status is no longer only a Basic Info field row |
| UX-A12 | Command-driven records get a declared **lifecycle spine** (`work_order`, `quote`, `service_visit`, `invoice`): happy path stages + interrupts (`blocked`) + aliases (`reopened`, `returned`) + off-spine terminals (`cancelled`, `void`, `rejected`, `declined`, `expired`, `withdrawn`) |
| UX-A13 | Stage bar shows **Step n of N** plus per-stage reached time, dated only from governed domain events / authoritative timestamp columns; undated stages stay blank rather than inferred |
| UX-A14 | Detail header is **sticky** (`top-16` under the mobile shell header, `top-0` on desktop) with a frosted full-bleed band, so identity, status and commands stay reachable in long records |
| UX-B6 | Workflow event trail resolves the actor to a person via shared `resolveActorDisplays`; system/API actors read as **System**; an unresolvable actor id is omitted rather than printed |

**Batch 5 follow-up (header toolbar at laptop widths):**

| ID | Decision |
| --- | --- |
| UX-A15 | Toolbar shares the title row only from `xl`; between `sm` and `xl` it takes a **full-width row of its own** rather than being squeezed into the leftover column, where every command wrapped onto its own line |
| UX-A16 | Identity block gets `min-w-0 flex-1` so the record name truncates and the toolbar keeps its natural width (`shrink-0`); previously the un-shrinkable title starved the toolbar |
| UX-A17 | At most **3 state commands** keep their own button (fits a full approve / decline / return set); further commands spill into `…` ahead of the escape hatches, so the header stays bounded as modules add commands |
| UX-A18 | Detail grid columns and field rows carry `min-w-0` + `break-words`, so long identifiers (`G3-…-F`, `Q-G3-…`) wrap instead of forcing the whole page into horizontal scroll at ~1024px |

Follow-up from Batch 5, resolved as a catalog contract rather than a UI tweak:
the lifecycle spine and the record command surface now live on the Module
manifest (`domain.aggregates[].lifecycle`, `domain.commands[].intent` /
`requiresReason` / `availableWhen` / `initiatedFrom` / `icon`). Catalog
validation rejects a state that is not classified exactly once, and both the
office detail page and the mobile visit page consume
`GET /objects/{key}` + `GET /objects/{key}/records/{id}/commands` instead of
keeping their own copies. Status badges on office detail and the mobile
work-order / quote / visit surfaces share one tone → class mapping derived
from the declared lifecycle (no per-status Tailwind tables). The earlier
mobile drift (`visit.submit_work` missing; quotes badge keyed as `review`)
is closed by construction.

Automatable regressions (e.g. persona absent on `/access`, no raw `usr_` on My Work for seeded tech) can later fold into **G2**; pure copy/hierarchy stays G3 backlog. Customer portal status vocabulary and planning bucket colours remain a later convergence step.

This catalog is the **experience debt backlog** that G3 is meant to produce. Closing UX-P1 items should be a release-candidate polish gate even when G3 sample status stays PASS.
